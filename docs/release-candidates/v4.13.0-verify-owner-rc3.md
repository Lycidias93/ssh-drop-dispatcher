## Dispatch workflow contract

`dispatch-file --wait` does not duplicate `process_file()`.

```text
preflight -> existing dispatcher scan -> wait-delivery -> receipt
```

A started delivery reports:

```text
scan_scope=existing_queue
automatic_requeue=no
remote_sha_required=yes
```

A local preflight rejection before scan start reports:

```text
scan_scope=not_started
```

No automatic retry/requeue, quarantine deletion, network self-healing or payload execution is introduced.

## Safety boundaries

RC3 does not change filename routing, target drop directories, dispatcher-owned remote syntax verification, remote SHA-256 parity, fail-closed Bash, BerylAX `sh`/`scp -O`, host payload non-execution, Python delivery policy, DNS, HA, VIP, default/static routes, MagicDNS or subnet routes.
