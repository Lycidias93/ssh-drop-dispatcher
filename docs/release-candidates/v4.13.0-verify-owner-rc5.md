## Goal

RC5 expands the secure standalone WebUI from status/control/diagnostics into safe day-to-day Dispatcher administration while keeping the delivery engine and verification ownership fail-closed.

Primary areas:

1. typed Host / SSH / target configuration;
2. configuration import/export with preview and rollback;
3. backup/restore UX built on the existing Dispatcher backup format;
4. host readiness/test workflow integrated with the existing bounded job model;
5. reusable generic primitives contributed back to `Lycidias93/android-root-module-webui-template` rather than implemented as SDD-only frontend forks.

## Shared-template dependency

RC5 must not silently fork the WebUI core.

Generic work belongs in `Lycidias93/android-root-module-webui-template`, currently tracked in `docs/ROADMAP_V0_3.md`:

- typed collection/profile editor;
- schema-versioned bounded import/export;
- validate/preview/apply workflow;
- reusable transaction/rollback UX;
- secret-aware export policy metadata.

RC5 pins a concrete template commit and core version only after those primitives are implemented and verified. Floating `main` is forbidden.

## Host and SSH configuration

The WebUI should provide a typed Target / Host editor rather than a raw `ssh_config` textbox.

Per-target fields should cover the existing Dispatcher model where applicable:

- target name / stable identity;
- enabled state;
- role;
- SSH host/address;
- SSH user;
- SSH port;
- remote drop directory;
- remote shell profile (`bash` or `sh`);
- SCP profile (`default` or legacy `-O` where required);
- SSH key reference selected from an allowlisted local key inventory;
- relevant delivery-policy overrides only when the backend already supports them.

Rules:

- no arbitrary command field;
- no raw SSH-config editor;
- no browser-controlled arbitrary filesystem path reader/writer;
- host/address, user, remote path and key reference are operationally sensitive and stay out of normal redacted status/diagnostics;
- private SSH key bytes are never displayed in the browser;
- BerylAX invariants remain explicit (`sh` + `scp -O`);
- verification owner remains Dispatcher and remote SHA remains required.

The current `sdd-setup-target.sh` behavior is an implementation reference, not the browser API. RC5 should factor its useful validation/generation logic into non-interactive typed adapter helpers instead of driving the interactive wizard from WebUI.

## Apply transaction

Host/SSH edits use an explicit transaction:

1. browser edits a typed in-memory collection;
2. server validates declared field types, sizes and record count;
3. adapter validates SDD-specific names/ports/shell/SCP/path/key-reference rules;
4. preview renders additions, edits, disables and removals without mutation;
5. readiness checks report blocking issues separately from apply;
6. apply creates a complete rollback snapshot before first productive write;
7. adapter atomically regenerates the existing Dispatcher target configuration and SSH config outputs;
8. config lint and local Dispatcher reload/health verification run;
9. optional target tests run as separate bounded jobs;
10. failure triggers rollback or exposes an explicit rollback action/state.

No DNS/HA/VIP/default/static route/MagicDNS/subnet-route mutation is part of host editing.

## SSH key handling

RC5 distinguishes key references from key material.

Allowed WebUI behavior:

- list allowlisted Dispatcher-owned key identities by safe label/fingerprint;
- select an existing key reference for a target;
- generate a new Dispatcher-owned key only through an explicit declared action with confirmation and rollback/error handling;
- display/copy the public key when intentionally requested;
- test which key reference authenticates for a target through a bounded job.

Not allowed in normal Host editor/import/export:

- display private key bytes;
- paste arbitrary private keys into generic configuration fields;
- export private keys in the default configuration export;
- choose arbitrary key paths outside the Dispatcher-owned allowlist.

Existing CLI backup support for private keys remains a separate high-risk path until an RC5 browser contract for it is deliberately proven.

## Import and export

RC5 should reuse the existing Dispatcher backup/restore domain rather than inventing an incompatible format. Existing backup documentation already covers:

- `manifest.env`;
- `config.env`;
- `config/targets.d/*.conf`;
- `ssh/ssh-config.dispatch`;
- `ssh/known_hosts`;
- public SSH keys;
- private SSH keys excluded by default.

WebUI UX should expose at least two safe concepts:

### Configuration export

Portable/admin export intended for normal use:

- schema/version metadata;
- Dispatcher settings;
- target records;
- SSH host metadata needed to reconstruct aliases;
- public key/fingerprint metadata where safe;
- no private key bytes;
- no token/credential contents;
- secret/write-only notification values redacted or represented only as configured/reference state.

### Backup export

Adapter-owned ZIP using the existing backup format. Default remains private-key-free.

If private-key backup is ever exposed in WebUI, it must be a separate danger operation with exact confirmation, clear local-only warning and dedicated device proof. It is not required for initial RC5 acceptance.

### Import

Import is never one-click overwrite:

1. upload to private WebUI runtime directory with strict size limit;
2. inspect archive/JSON structure without mutation;
3. reject traversal, symlinks, undeclared paths and wrong module/schema versions;
4. show redacted preview/diff;
5. validate host/SSH/target model;
6. require explicit confirmation;
7. create pre-import backup;
8. apply atomically;
9. lint/health verify;
10. expose rollback result.

Cross-module or malformed imports fail closed.

## UI structure

Proposed navigation additions:

- **Targets** — existing read-only Target Matrix plus `Edit targets` mode;
- **SSH** — key references/fingerprints, known-host state and bounded connectivity tests;
- **Backup** — Export configuration, Export backup, Import/preview, rollback history;
- keep Overview, Settings, Control, Diagnostics, Queue/Inventories.

Use progressive disclosure: normal users see concise cards/forms; raw evidence stays under Diagnostics.

## Acceptance gates

RC5 is not accepted merely because the UI renders.

Required proof includes:

- RC4 delivery-core blobs remain pinned or any intentional backend change is separately reviewed;
- typed host editor cannot construct arbitrary shell/config text;
- no host/remote/key fields leak into redacted status/diagnostics;
- add/edit/disable/remove previews are accurate against fixtures;
- BerylAX profile remains `sh` + `-O` through edit/export/import roundtrip;
- default export contains no private key or token contents;
- import rejects traversal, undeclared paths, wrong schema/module and oversized input;
- import preview performs no productive write;
- apply/restore creates rollback before first write;
- no-op roundtrip of current live configuration returns equivalent effective config;
- target tests remain bounded jobs and use Dispatcher-owned verification semantics;
- WebUI remains loopback-only with one-time bootstrap and HttpOnly session;
- normal Dispatcher health is independent of WebUI process lifetime;
- postboot installed-runtime verify ends with `RESULT: CG_INSTALLED_RUNTIME_VERIFY_DONE outcome=success workflow_exit_code=0`.

## Non-goals for initial RC5

- generic file manager;
- generic terminal/shell;
- arbitrary SSH config editor;
- browser import/export of private key bytes;
- DNS/route/Tailscale configuration;
- automatic target provisioning on remote hosts without a separate typed contract;
- public release/update promotion by implication.
